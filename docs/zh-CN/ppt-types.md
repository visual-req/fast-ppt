# PPT 类型说明

`fast_ppt` 在生成前必须先确定 `deck.type`。  
当前固定支持四类：

- `课件类`
- `方案类`
- `汇报类`
- `演示类`

这不是命名差异，而是四种完全不同的结构节奏。  
类型一旦选错，后面就很容易出现：

- 章节顺序不对
- 图页比例不对
- layout 选型跑偏
- 文案密度和阅读节奏不对

## 一页看懂四种类型

| 类型 | 核心目标 | 默认结构关键词 | 最适合的场景 |
|------|----------|----------------|--------------|
| `课件类` | 把知识讲会 | 知识点 / 解释 / 示例 / 练习 / 小结 | 培训、授课、分享、内训 |
| `方案类` | 说明问题并推动采纳 | 目标 / 现状 / 差距 / 方案 / 路径 / 风险 | 售前方案、咨询方案、技术方案 |
| `汇报类` | 快速传达结论并推动决策 | 结论 / 数据支撑 / 偏差 / 动作 / 决策项 | 管理汇报、阶段汇报、经营复盘 |
| `演示类` | 吸引注意并强化记忆 | 场景 / 亮点 / 能力 / 流程 / 效果 / 收尾 | 产品演示、路演、发布、功能展示 |

## 怎么快速判断该选哪类

先问自己这套 PPT 最主要的目的是什么：

- 目的是“让听众学会某个知识或方法”：
  选 `课件类`
- 目的是“让对方接受你的方案或思路”：
  选 `方案类`
- 目的是“让管理者快速看到结论、风险和下一步”：
  选 `汇报类`
- 目的是“现场展示产品、能力或亮点，增强兴趣和记忆”：
  选 `演示类`

一个实用判断法：

- 以“教学完整性”为先：`课件类`
- 以“说服采纳”为先：`方案类`
- 以“结论和决策”为先：`汇报类`
- 以“展示效果和节奏”为先：`演示类`

## 四种类型的详细差异

### 1. `课件类`

核心目标：

- 把知识讲清楚
- 降低理解门槛
- 让听众能跟上、能吸收、最好还能练一遍

默认结构：

- 背景 / 为什么要学
- 核心概念
- 原理或方法拆解
- 示例 / 案例
- 练习 / 讨论
- 小结 / 带走什么

页面特征：

- 页数通常相对更多
- 不怕拆页，怕的是一页塞太多知识动作
- 经常需要“概念页 + 解释页 + 示例页 + 练习页”连续出现
- 文案更像老师可直接讲，而不是写给老板看的摘要

适合的输入材料：

- 培训提纲
- 课程草案
- 教学讲稿
- 知识总结
- 方法论说明

不适合的情况：

- 只是想快速汇报进展
- 只是想推一个解决方案
- 只是想做一场产品展示

常见误判：

- 把培训课做成 `汇报类`，结果只剩结论，没有教学展开
- 把复杂概念压成一页 bullet，导致学不会

建议节奏：

- 宁可多 3-8 页，也不要把多个知识动作挤在同一页
- 对复杂概念、方法框架、系统构成，默认主动拆页

### 2. `方案类`

核心目标：

- 说明问题
- 提出方案
- 证明可行
- 推动对方接受或批准

默认结构：

- 背景与目标
- 现状与问题
- 差距与约束
- 总体方案
- 分项设计
- 实施路径
- 收益、风险与保障
- 建议与下一步

页面特征：

- 强调逻辑闭环
- 不能只有文字论证，通常需要架构图、流程图、路线图、分层图
- “问题、方案、计划、风险”一般不应被压在同一页
- 需要兼顾完整性和可落地性

适合的输入材料：

- 项目方案
- 售前材料
- 架构设计说明
- 咨询报告草案
- 立项建议

不适合的情况：

- 重点是教学和知识传递
- 重点是管理层快速看结论
- 重点是做现场产品演示

常见误判：

- 把方案做成 `汇报类`，导致只有结论，缺少完整论证
- 把方案做成 `演示类`，视觉上热闹但决策信息不完整

建议节奏：

- 总体方案、分项设计、实施路径、风险保障通常都要单独展开
- 先保证结构闭环，再考虑压页数

### 3. `汇报类`

核心目标：

- 快速传达结论
- 用事实支撑判断
- 推动决策或资源支持

默认结构：

- 结论先行
- 数据与事实支撑
- 当前进展
- 关键问题 / 偏差
- 建议动作
- 决策项 / 支持请求
- 下一步安排

页面特征：

- 结论密度高
- 阅读路径短，适合管理层快速扫读
- 重要判断后面通常需要紧跟支撑页
- 关键请求不能埋在普通说明页里

适合的输入材料：

- 周报 / 月报
- 项目阶段汇报
- 管理汇报
- 经营复盘
- 专项进展说明

不适合的情况：

- 需要完整教学
- 需要系统阐述大方案
- 重点是现场展示产品亮点

常见误判：

- 把汇报做成 `方案类`，导致前半部分铺垫太长，结论太晚出现
- 把汇报做成 `课件类`，导致页数过多、节奏过慢

建议节奏：

- 重要判断默认至少配一页事实支撑
- 如果最终目的是拍板，必须显式出现“决策项 / 需要的支持”

### 4. `演示类`

核心目标：

- 吸引注意
- 建立兴趣
- 强化记忆
- 促成认可

默认结构：

- 场景引入
- 核心主张 / 亮点
- 能力展示
- 使用流程
- 效果对比
- 行动引导 / 收尾

页面特征：

- 更强调画面冲击和叙事节奏
- 图、流程、对比、场景页占比更高
- 重点页面需要“记忆点”，不适合长段说明
- 往往是“亮点页 + 能力页 + 场景页 + 效果页”成组出现

适合的输入材料：

- 产品介绍
- 功能演示脚本
- 发布会讲稿
- 路演提纲
- 样板案例展示

不适合的情况：

- 需要完整讲授知识
- 需要完整论证方案可行性
- 需要快速对管理层汇报结论

常见误判：

- 把演示做成 `汇报类`，结果全是结论和 bullet，缺少吸引力
- 把演示做成 `方案类`，结果论证太重，现场节奏变慢

建议节奏：

- 不要让同一页同时承担场景、卖点、流程、效果四种任务
- 核心亮点要优先拆成多页，而不是堆在一页上

## 最容易混淆的边界

### `方案类` vs `汇报类`

看重点是“说服采纳”还是“汇报结论”：

- 要完整论证方案、争取接受：`方案类`
- 已有方向，重点是汇报现状、偏差和决策项：`汇报类`

### `汇报类` vs `演示类`

看听众是在“做判断”还是“看展示”：

- 管理层需要快速做判断：`汇报类`
- 观众需要被吸引、被展示打动：`演示类`

### `课件类` vs `方案类`

看你想让对方“学会”还是“采纳”：

- 学会概念和方法：`课件类`
- 接受方案和路径：`方案类`

## 类型会影响哪些地方

类型一旦确定，至少会影响这些层：

- `outline` 的章节结构
- 页序和节奏
- 图页比例
- `layout_type` 选择
- 文案密度
- detail 阶段的拆页策略
- 最终 viewer 里的阅读体验

所以正确顺序是：

1. 先判断类型
2. 再生成 `outline.json`
3. 确认结构后再生成 `deck.json + slides/*.json`

## 实操建议

第一次上手时，建议先做这两步：

1. 先读一遍这页，明确当前项目属于哪一类
2. 再回到 [快速开始](getting-started.md) 继续走 `outline -> detail -> preview`

如果你已经知道自己属于哪类，也建议在需求里明确写出，例如：

```text
请生成一套方案类 PPT
请生成一套汇报类 PPT
请生成一套演示类 PPT
```

这样 Skill 在起草 `outline.json` 时会更稳定。
